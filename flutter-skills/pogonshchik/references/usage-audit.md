# Разбор расхода и размеченный запуск

Читай только при просьбе измерить расход, найти лишние чтения или провести сравнительный запуск. Это отдельная задача от проверки заполненности окна в context-handoff.md.

## Сначала существующий журнал

Не начинай новую разработку только ради диагностики, если доступен локальный журнал нужного чата. Вызовы инструментов и счётчики уже записаны. Выгрузи только безопасные метаданные:

```bash
python3 /Users/davidyolkin/.codex/skills/pogonshchik/scripts/session_usage_trace.py --thread-id <точный-ID> --output-dir <папка-отчёта>/<роль>
```

Для руководителя и исполнителя — отдельные каталоги. Сначала прочитай summary.json; requests.jsonl и actions.jsonl открывай только для конкретных номеров запросов/действий. Не загружай полный rollout, переписку, код или весь trace в контекст и не заставляй исполнителя пересказывать свой журнал.

Выгрузка содержит фактические usage-счётчики запросов, фазы при наличии меток, имена явно прочитанных путей, объём выводов команд и число изображений. Она не экспортирует тела исходников, ответов инструментов, изображений или рассуждений. Анализатор не открывает исходники приложения. Путь чтения и категория команды определяются эвристически; это не полный системный file-access trace.

Сверяй сумму запросов с cumulative counter. Разделяй cached input, uncached input и output; reasoning уже входит в output. Некэшированный ввод может быть старой историей после cache miss. Отдельно проверь резкие промахи кэша, первый контекст, повторные чтения, обрезанные выводы и длинные последовательности runtime-проверок. У изображения нет цены в токенах, вычисляемой из длины base64. Расход генерации изображений/внешних инструментов не выдавай за полностью учтённый этими текстовыми счётчиками.

Не называй все повторения потерями: код мог измениться, а повторная проверка — поймать дефект. Точного тарифицируемого расхода на каждый файл журнал не даёт. Подтверждённые лишние чтения отделяй от полезной диагностики и предположений. Не обещай экономию без сопоставимого запуска; деньги и лимит подписки не выводятся из простой суммы токенов.

## Если нужен новый измерительный запуск

Зафиксируй объём, модель/режим, критерии качества и исходный счётчик руководителя. Новый исполнитель должен начать без старой истории. Создание нового приложения/чата — только по поручению пользователя; условное «если журнал недоступен» не выполняй, когда существующий журнал достаточен.

При смене этапа добавь в начало JS-кода уже необходимого вызова functions.exec одну строку:

```javascript
// usage-stage: discovery
```

Другие этапы: design, implementation, tests, release, capture, review, handoff. На новом ходе укажи этап заново. Метка действует до следующей; анализатор берёт её из вызова. Не делай отдельные вызовы, сообщения или документы ради меток. Не вставляй JS-комментарий в shell-команду или apply_patch. Этап описывает действие запроса, а не происхождение всех токенов его накопленной истории.

Достаточно обычного отчёта о результате и ссылки на выгрузку руководителя. Не добавляй обязательный подробный self-report после каждого шага: он увеличивает контекст и менее надёжен, чем фактические вызовы и счётчики.
